## 2026-09-13
* **Implementation**: Added syntax highlighting to `okf site` code blocks via a vendored shiki bundle (`crates/okf-web/assets/vendor/shiki.min.js`, 9.6 MB IIFE of npm `shiki` 3.23.0, MIT). Follows the mermaid precedent exactly: rendered client-side (highlighting at build time would put a JS runtime in the build chain, per the [decision record](decisions/okf_web_static_site.md)), loaded only on pages with language-tagged fences, escaped source kept as the no-JS fallback. Deviations forced by shiki: it publishes ESM only (no IIFE dist since v1), so the bundle is an offline esbuild IIFE of a small entry (`shiki-entry.mjs`); and shiki's JavaScript regex engine drops `rust`/`toml`/`ini`/`diff`/`console`/`go`, so the Oniguruma engine with **inlined** WASM is used — zero runtime fetches, `file://` still opens. One dual-theme render (`defaultColor: false`): token colors ship as `--shiki-light`/`--shiki-dark` CSS variables resolved by the site stylesheet under `.dark`/`.light`, so theme toggling is free (no re-render, unlike mermaid). `okf site` summary now reports code pages; NOTICE/vendor README/okf-web docs updated.
* **Reorganization**: Moved the [okf-site vs okf-web decision record](decisions/okf_web_static_site.md) from `architecture/` to `decisions/` — it is a decision-plus-rationale ADR, and `architecture/` now holds only the descriptive workspace-architecture concept. Repointed its inbound links: the [plan](plans/okf_web_plan.md), `crates/okf-web/Cargo.toml`, and `crates/okf-web/README.md`. Also fixed the ADR's own `../plans/okf_web_plan.md` link (was `../../plans/`, which resolved outside the bundle) and the `plans/index.md` heading (`# Decision` → `# Plan`).
